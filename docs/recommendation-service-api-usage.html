Recommendation Service API Usage — Eagle-Fusion Frontend

Scope: Aastrika Sphere web frontend (eagle-fusion). Maps the 15 recommendation-service endpoints (7 functional groups) and their uiproxy routes against actual usage in this repository.

Generated: 2026-06-26  |  Service base: RECOMMENDATION_API_BASE_V2 (default http://localhost:8086)

Bottom line: This web frontend touches only the Course Recommendation and Rating groups, and only through search/rating routes that power course cards.
  • Actively used — publicSearch/getcourse (via SEARCH_V8PUBLIC) and bulkRatingLookup (indirectly, via ratingsSearch/getCourses).
  • Defined but not wired — courseRemommendationv2 (GET) and courseRecommendationCbp (POST CBP): service wrappers exist, but no component calls them.
  • Not used at all — Competency Reports, Data Summary, CBP Activity Logs, Learner Path, Homepage Config, and the recommendationEngineV2 portal route.

Terminology: "Used" = a constant is sent over HTTP from a method that has a live caller. "Defined / not wired" = the constant and its service wrapper exist but no component invokes the wrapper (dead code). "Not used" = no reference to the path or constant anywhere in source. All paths are declared in src/app/constants/apiConstants.ts — never hardcoded.

2. Used APIs — where & what we render

2.1   Rating: POST /bulkRatingLookup  →  ratingsSearch/getCourses

Not called directly. The frontend hits SEARCH_V6PUBLIC / PUBLIC_CONTENT_SEARCH (both /public/v8/ratingsSearch/getCourses); the service enriches each result with rating data via bulkRatingLookup server-side. This is the workhorse course-search call — Live courses filtered by category / source / language / identifier, sorted by lastUpdatedOn.

Request shape (typical):

{
  request: {
    filters: {
      primaryCategory: ['Course'],
      contentType: ['Course'],
      status: ['Live'],
      sourceName: '<org / partner>',   // optional
      lang: 'hi',                          // added when Hindi
      identifier: ['<courseId>', ...]   // optional (by-id lookups)
    }
  },
  query: '',
  sort: [{ lastUpdatedOn: 'desc' }]
}

Called from:

LocationMethodWhat is shown
src/organisations/org-home-service.service.ts getSearchResults(), getLiveSearchResults() Org-home landing page — list of Live courses; identifiers cross-checked against the user's enrolments to show enrolled state.
project/ws/app/.../org/org-service.service.ts getSearchResults(), getSearchResultsById(), getLiveSearchResults(), getTopLiveSearchResults() Org landing page sections — course cards per section (by source / identifier list / language).
project/ws/app/.../search/apis/search-api.service.ts getSearchCompetencyCourses(), getSearchV6Results() Main search results page — result grid + facet/filter sidebar (res.result.facets).
library/ws-widget/collection/.../widget-content.service.ts:330,339 searchV6(), publicContentSearch() Content-strip widgets (single & multiple) on home / landing pages — horizontal course carousels.

3. Defined but not wired (dead wrappers)

3.1   GET courseRemommendationv2  →  COURSE_RECOMENDATION

Constant COURSE_RECOMENDATION(profession) → /public/v8/mobileApp/courseRemommendationv2?profession=…, wrapped by widget-content.service.ts:407 fetchCourseRemommendations(). No component calls this method — the only reference is its own definition.

3.2   POST courseRecommendationCbp  →  COURSE_RECOMMENDATION_V2

Constant COURSE_RECOMMENDATION_V2 → /public/v8/mobileApp/publicSearch/courseRecommendationCbp (the mobileApp variant, not the protected/v8/recommendationEngineV2/... portal route). Wrapped by widget-content.service.ts:419, which builds a designation-based payload:

{
  offset: 1, limit: 300,
  search_text: req.designation,
  search_fieldnames: ['rolesMapped'],
  course_status: 'Live',
  primaryCategory: 'Course',
  orgId: req.orgId,
  language: req.language
}
Attention: Both fetchCourseRemommendations() and COURSE_RECOMMENDATION_V2() are defined but have no callers anywhere in the repo — effectively dead code. The intended use (role/designation-based "recommended for you" cards) is not wired into any component. Flag for cleanup or wiring.

3.3   GET /course/source_name/users  →  ENROLLED_USER (test-only)

Constant ENROLLED_USER → apis/protected/v8/userEnrolledInSource, wrapped by org-service.service.ts:115 getEnroledUserForCourses(sourceName). This proxy path corresponds to the Data-Summary source_name/users endpoint. The wrapper is currently referenced only in the org component spec (org.component.spec.ts) — no production component invokes it, so it is not exercised by real page flows today.

4. Not used (no references in this repo)

  • Course Recommendation — recommendationEngineV2 (GET /course/recommendation): no recommendationEngine references at all.
  • Competency Reports — passbook, assessment, course_enroll: no competencyReporting references.
  • CBP Activity Logs (cbp_activity_logs): not referenced (also has no proxy route).
  • Learner Path (GET/POST learnerpath): no learnerPath / learnerpath references.
  • Homepage Config (all CRUD on homepageconfig): no homepageconfig references.

Per the service's "Used By" mapping these are consumed by the mobile App and/or portal-CBP clients, not by this web frontend.
