01
Feature Overview

What is the ASHA Competency Learning feature?

ASHA workers (Accredited Social Health Activists) and ANMs are assigned a set of health competencies based on their designation and organisation. Each competency is split into 5 levels. A user proves a level by either completing a self-assessment quiz or finishing a course. The home dashboard shows their progress across all competencies for their role, with the next step surfaced automatically.

The feature is organisation-scoped and designation-scoped: two users in different organisations, or different designations in the same organisation, see entirely different sets of competencies, courses, and progress trackers.

When this feature shows: Only when competencyRoles === true AND showanmHome === true. Both flags must be truthy. If either is false, the standard enrolled-course list renders instead.

Designation values currently driving the ASHA layout (found in learnerPath.config.json) include but are not limited to: ASHA-WORKER, ANM-BIHAR, GNM-MP, and other state-specific role keys. The exact set is driven by the S3 config, not hardcoded in the app.

External Data

S3 configuration files

Two JSON files in S3 drive the entire feature. Both are fetched fresh when online and fall back to localStorage when offline.

S3 https://aastar-app-assets.s3.ap-south-1.amazonaws.com/ekshamataOrgConfig.json
Organisation metadata — org names, video intro links, channel IDs. Used to set showanmHome by checking if the user's rootOrgId exists as a key in the competency config.
Fetched in getOrgData() → cached as APP_ORG_DATA
S3 https://aastar-app-assets.s3.ap-south-1.amazonaws.com/learnerPath.config.json
The master competency config. Maps each organisation ID → designation → competency list. Each competency has an ID and 5 level descriptors, each level maps to course IDs per language. This is the single source of truth for which competencies a user sees.
Fetched in getCompetencyData() → cached as APP_COMPETENCY_DATA. Note: URL has ?v=timestamp — always cache-busted on fetch.

        {

            "id": "42",              // competency numeric ID (string)
            "name": "Family Planning",

              "competencyLevelDescription": [
                {

API Reference

Assessment submission

POST /apis/public/v8/mobileApp/v1/competencyAssessment/submit
Dedicated quiz-submission endpoint for ASHA self-assessments. Used instead of the standard /submitAssessment endpoint. Accepts the same quiz request payload as the regular assessment submit but is routed through a competency-aware backend that scores and stores the pass/fail result.
Called via quizService.competencySubmitQuizV2(req) from the @aastrika_npmjs/comptency self-assessment module
PATCH /apis/public/v8/mobileApp/kong/user/v1/passbook
Updates the passbook (certification record) after an assessment is completed. Called alongside the assessment submit to maintain certification state.
Two different assessment submit endpoints exist. Standard courses use /mobileApp/submitAssessment. ASHA competency self-assessments use /mobileApp/v1/competencyAssessment/submit. The distinction is made in the quiz plugin by checking the isAsha flag passed in navigation query params.

Data Pipeline

The 7-step ASHA data pipeline

All pipeline logic runs inside getAshaData() in MobileDashboardComponent, using utility functions from home-page.util.ts. The pipeline is built as a reactive chain (RxJS mergeMap + tap).

1
Load S3 competency config
Fetch learnerPath.config.json from S3 (or localStorage if offline). Result stored in competencyHomeData. Simultaneously, fetch org config to get showanmHome flag.
getCompetencyData() → APP_COMPETENCY_DATA
2
Process org + designation → extract competency IDs and levels
processCompetencyData(competencyHomeData, currentOrgId, designation) looks up the user's designation inside their org's config block. Returns: isDesignationInRoles (boolean), competencyIds[] (string array), competencyLevels[] (flattened level objects).
processCompetencyData() → competencyLevelData()
3
Guard: if designation not in roles → stop
If isDesignationInRoles === false or orgData === null, getCompetencyInfo() returns null and the pipeline exits. The ASHA UI is not rendered.
getCompetencyInfo() → null guard
4
Fetch all competency courses for user's language
POST to /getCourses with filter competency: [true] and lang: defaultLang. Returns all live competency courses for that language. Result is res.result.content[].
POST /apis/public/v8/publicSearch/getCourses
5
Format courses: parse competencies_v1 + attach levels
getFormattedCompetencyCoursesWithFilter(res, competencyLevelsData, roleCompetencyData) runs: parse competencies_v1 JSON string → extract competencyId → attach matching level objects from step 2 → filter to only include courses whose competencyID is in the user's role competency list.
getFormattedCompetencyCoursesWithFilter() in home-page.util.ts
6
Fetch user's progress records
GET /learnerpath?userId={id}. If this call fails, the pipeline continues gracefully (empty progress = no progress shown, user starts from zero). Result is progressData.data[].
GET /apis/public/v8/mobileApp/learnerpath?userId=
7
Merge progress + partition into completed / in-progress
mergeProgressData(ashaData, progressData.data) attaches progress to each competency. Then setCoursesState(ashaData) partitions into completedCourses[] (5/5 levels passed) and inProgressCourses[] (sorted, first item gets expand: true).
mergeProgressData() + setCoursesState()

The pipeline is written with mergeMap chaining in RxJS, not forkJoin, so steps 4 and 6 execute sequentially (not in parallel). This is intentional — step 6 depends on the result of step 5 to know whether to bother fetching progress.

10
User Interaction

The three Start / Continue paths

When a user taps the primary CTA on a competency card, startSelfAssessment(data, event) runs. It branches into three distinct paths based on progress state:

Path A — No progress
!data.progress || data.progress.length === 0
  • Navigate to self-assessment (level 1 quiz)
  • router.navigate(['app/user/self-assessment'], { queryParams: data })
  • Button label: Start
Path B — Admin-granted progress
every progress entry has contentType === 'admin'
  • Skip computed logic — admin progress is not earned
  • Navigate directly to self-assessment
  • Stepper shows all levels as blank (not completed)
  • Button label: Start
Path C — Has earned progress (course or selfAssessment)
earnedProgress.length > 0 (excludes admin entries)
  • Find next incomplete level: minimum level in [1,2,3,4,5] not in completedLevels[]
  • Find progress entries for that level. If none, fall back to highest completed level
  • Select the best entry: priority → passFailStatus === 'Pass' && contentType === 'course', then any
  • If selected entry is contentType: selfAssessment, passFailStatus: Pass → navigate to self-assessment (next step is a course)
  • Otherwise → look up course ID for (competencyID, nextLevelId, lang) from getCourseId()
  • POST to /getCourses with that identifier to get current batchId
  • Navigate to /app/toc/{courseId}/overview with ASHA query params
  • Button label: Continue

Navigation to course TOC passes the following query params:

query params passed to /app/toc/{courseId}/overview
{
  primaryCategory: "Course",
  batchId: "<batchId from getCourses response>",
  competencyid: "<competencyID>",    // used by quiz to submit to correct endpoint
  levelId: 3,                        // the level being attempted
  courseid: "<contentId from ashaData>",
  isAsha: true                        // ← key flag that routes to competency assessment submit
}
The isAsha: true flag is critical. The quiz plugin reads this from navigation extras and uses competencySubmitQuizV2() instead of submitQuizV2(). Without it, assessment results go to the wrong backend endpoint and are not stored in the learner path.

Contextual state data is also stored before navigation via cordovasvc.setAshaData(ashaData) — this sets a temporary state object read by the course player and quiz components:

data stored before navigation (via ContentCorodovaService)
{
  isAsha: true,
  batchid: "<batchId>",
  contentid: "<courseIdentifier>",
  competencylevel: 3,
  completionpercentage: 0,
  progress: "course",
  competencyid: "42",
  competencyName: "Family Planning"
}

Data Model

How progress data is structured and merged

The progress pipeline in mergeProgressData() and the supporting functions in home-page.util.ts is the most logic-dense part of the feature. Here is an exact description of each step:

A
Normalise raw progress entries
mapProgress() maps API field names to camelCase: competencylevel → levelId, competencyid → competencyId. Then groupBy(competencyId) groups entries per competency. Duplicates within a group are removed by unionBy(passFailStatus + competencyId + levelId).
B
Build course → levels map
groupLevelsByCourse(levels) creates a Map<courseId, levelNumber[]>. This enables the pass-propagation logic: knowing which levels share a courseId.
C
Identify completed courses (for pass propagation)
Any progress entry where passFailStatus === 'Pass' AND contentType === 'course' → find the courseId from the matching level → add to completedCourses Set.
D
Expand pass to all sibling levels
For each courseId in completedCourses, find ALL levels that map to it. For each of those levels, create a synthetic Pass progress entry (if not already present). This is the unified-course propagation.
E
Combine non-course progress with expanded course progress
selfAssessment and admin entries are preserved as-is. Merged with the expanded course entries. Final dedup by levelId + contentType + passFailStatus.
F
Partition: completed vs in-progress
partitionCompletedAndInProgress(): a competency is completed when it has exactly 5 passFailStatus === 'Pass' entries. Partial progress = in-progress. Both buckets are sorted by competencyID numerically.

Admin-granted progress special case: if every progress entry for a competency has contentType === 'admin', the stepper shows blank (all levels unstarted), the completion percentage is 0, and the CTA always navigates to self-assessment. This prevents admin-granted passes from appearing as "earned".

Completion percentage formula:

completion % — getCompletionPercentage()
completedLevels = filter(earnedProgress, { passFailStatus: 'Pass' }).length
totalPercentage = (completedLevels / 5) * 100
// capped at 100, showBtn = false when totalPercentage === 100

Implementation Guide

Porting to a web application

The following differences apply when building the same feature on web. The API contracts are identical — only the client-side patterns change.

1
Replace CordovaHttpService with Angular HttpClient
All API calls in the mobile app go through CordovaHttpService (which wraps @awesome-cordova-plugins/http for SSL pinning). On web, use standard HttpClient with an HttpInterceptor to attach the auth token. API endpoints and payloads are identical.
2
Replace localStorage cache with an in-memory service or session storage
The mobile app caches S3 configs in LocalStorageService for offline access. On web, cache in a service singleton (Angular service with providedIn: 'root'). Consider sessionStorage if you want cache invalidation on tab close.
3
Replicate the competency localStorage key for the npm package
If you use the same @aastrika_npmjs/comptency package, you must set localStorage.setItem('competency', JSON.stringify({...})) with { userName, profileData, language, id, hostPath, isMobileApp: false, session } before routing to the self-assessment module. Set isMobileApp: false on web.
4
Auth token: read from cookie or session, not Sunbird SDK
Mobile uses AuthService.getSession() from @aastrika_npmjs/sunbird-sdk for the JWT. On web, the token is typically available in a cookie set by the Keycloak/SSO flow, or directly accessible from the user's session object. Pass it as Authorization: Bearer <token> on authenticated routes (proxies/v8 endpoints).
5
The utility functions in home-page.util.ts are pure — copy them directly
All transformation logic (processCompetencyData, getFormattedCompetencyCoursesWithFilter, mergeProgressData, setCoursesState, partitionCompletedAndInProgress) is pure TypeScript with lodash. Copy these functions as-is into your web project. They have no Angular or Capacitor dependencies.
src/app/modules/home/util/home-page.util.ts
6
Replace ContentCorodovaService.setAshaData() with a state service
The mobile app stores navigation context in ContentCorodovaService before routing, then reads it in the quiz plugin. On web, use a shared Angular service or router state (router.navigate([...], { state: ashaData })) to pass context to the course player route.
7
Tablet detection: use CSS media queries, not Capacitor
Mobile uses commonUtilService.isTablet() which calls a Capacitor device plugin. On web, use window.matchMedia('(min-width: 768px)') or Angular CDK BreakpointObserver.
Summary of what to rebuild: Two service calls (getOrgData, getCompetencyData → S3), one POST to get courses, one GET for progress, one POST for course detail on navigation. All data transformation is pure functions you can copy directly. The isAsha: true flag and competency localStorage context are the two most critical integration points to get right.
